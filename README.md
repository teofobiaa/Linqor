# Linqor

**Linqor** — проект моста между двумя устройствами. Цель — обеспечить простой и контролируемый обмен данными между устройствами через браузерный интерфейс и QR-подключение.

> Проект находится на начальном этапе разработки. Описание ниже фиксирует согласованное направление и текущую структуру, а не заявляет о готовой реализации.

## Основная идея

Пользователь открывает Linqor на двух устройствах, подтверждает соединение с помощью QR-кода и получает общую рабочую сессию. В рамках сессии предполагается передавать данные и работать с ними с другого устройства.

Ключевые принципы:

- **QR-подключение** — быстрый способ инициировать соединение между устройствами.
- **Обязательная регистрация** — функции Linqor недоступны без учётной записи.
- **Работа с содержимым сессии** — просмотр истории и доступ к переданным материалам, включая скачивание файлов и копирование данных в буфер обмена.
- **Новая сессия при новом QR-подключении** — повторное соединение не должно незаметно продолжать старую сессию.
- **Контроль хранения** — временные данные не должны храниться бессрочно.
- **Минимизация расходов** — на первом этапе приоритет отдаётся бесплатным тарифам и бесплатной инфраструктуре без ущерба для базовой безопасности и надёжности.

## Планируемые возможности

- [ ] Регистрация и вход в аккаунт.
- [ ] Подтверждение подключения между устройствами через QR-код.
- [ ] Управление состоянием активной сессии.
- [ ] Передача текста и файлов.
- [ ] Просмотр содержимого сессии на подключённом устройстве.
- [ ] Скачивание файлов и копирование содержимого.
- [ ] Сохранение доступной истории с ограниченным сроком хранения.
- [ ] Корректное завершение сессии и очистка временных данных.

Список будет уточняться по мере проектирования и реализации.

## Технологическое направление

Предварительно выбранная инфраструктура:

| Компонент | Назначение |
| --- | --- |
| GitHub | Исходный код, версии, Issues, Pull Requests и CI |
| Cloudflare | Серверная инфраструктура и передача/хранение файлов |
| Supabase | База данных, аутентификация и пользовательские данные |
| GitHub Actions | Автоматические проверки и тестирование |

Конкретные сервисы Cloudflare, схема взаимодействия компонентов и технологический стек клиентского приложения будут зафиксированы отдельно после проектирования.

**Важно:** GitHub используется только для разработки. Пользовательские сообщения, фотографии и документы не должны храниться в репозитории.
