# Принятые проектные решения

Этот файл содержит только решения, которые уже были выбраны в ходе проектирования. Предположения и вопросы вынесены отдельно.

| Область | Решение | Статус |
| --- | --- | --- |
| Назначение | Мост для обмена данными между двумя устройствами | Зафиксировано |
| Подключение | QR-код используется для инициирования подключения | Зафиксировано |
| Подтверждение | Подключение требует подтверждения на уже авторизованном устройстве | Зафиксировано |
| Доступ | Без регистрации функции приложения недоступны | Зафиксировано |
| Аутентификация | Supabase Auth; вход по email и паролю, а также через Google OAuth | Зафиксировано |
| Связывание входов | Один аккаунт Linqor может иметь несколько способов входа; одинаковый подтверждённый email должен связываться безопасным механизмом Supabase Auth | Зафиксировано |
| Пароль архива | Пароль E2EE-архива отделён от способа входа в Linqor; вход через Google не заменяет пароль расшифровки | Зафиксировано |
| Подключение Google | Google OAuth 2.0 через Supabase Auth; минимальные scopes: openid, email, profile | Зафиксировано |
| Сессии | Новое QR-подключение создаёт новую сессию | Зафиксировано |
| Содержимое | Пользователь может просматривать содержимое сессии, скачивать файлы и копировать данные | Зафиксировано |
| Хранение | Для сохранённого содержимого используется ограниченный срок хранения; рабочий ориентир — 7 суток | Требует детализации правил |
| Инфраструктура | GitHub + Cloudflare + Supabase + GitHub Actions | Выбрано как направление |
| Данные GitHub | Пользовательские сообщения и файлы не хранятся в репозитории | Зафиксировано |
| Приоритет | Максимально использовать бесплатную инфраструктуру на первом этапе | Зафиксировано |

## Не следует считать решённым

- Конкретный язык и фреймворк клиентского приложения.
- Конкретные продукты Cloudflare и их распределение по задачам.
- Прямой P2P, серверный relay или гибридная передача.
- Протокол обмена сообщениями и файлами.
- Сквозное шифрование и схема управления ключами.
- Точная схема БД, таблиц и RLS.
- Лимиты размера файлов, пропускной способности и числа устройств.
- Точная семантика удаления: срок отсчитывается от создания, последней активности или завершения сессии.
- Поведение при закрытии вкладки и работе в фоне.

Изменение зафиксированного решения должно сопровождаться обновлением этого документа и соответствующей архитектурной документации.
